# 数据帧状态机方案

## 总体原则

数据帧会话由 APP 驱动。LINK 只维护传输子状态, 不决定业务阶段。

```
APP: 选择目标、推进 CFG/META/DATA/DONE、处理 CRC 和复位
LINK: 执行一条 APP 命令对应的一次帧交换
PHY: 执行 TX/RX 或 pending frag delayed TX
```

## Tag APP 状态机

```
IDLE
  |
  | 1s polling, choose target_id
  v
WAIT_CFG_ACK
  |
  | DATA_ACK
  v
WAIT_META
  |
  | DATA_FRAG(meta)
  v
PULLING
  |
  | all fragments received and CRC ok
  v
WAIT_DONE_ACK
  |
  | DATA_ACK
  v
IDLE
```

异常路径:

- `DATA_WAIT`: APP 延迟后重发当前命令。
- `DATA_ERROR`: APP 触发 `LINK_CMD_SESSION_RESET`, 回到 `IDLE`。
- `DATA_FAIL`: APP 丢弃当前 session, 回到 `IDLE`。
- CRC 失败: APP 不递增 frag_id, 重发当前 `PULL`。

Tag APP 下发命令:

| APP 状态 | 命令 |
|----------|------|
| `WAIT_CFG_ACK` | `LINK_CMD_SEND_CFG_REQ(target_id, session_id)` |
| `WAIT_META` | `LINK_CMD_SEND_CTRL(target_id, session_id, GET_INFO, 0)` |
| `PULLING` | `LINK_CMD_SEND_CTRL(target_id, session_id, PULL, frag_id)` |
| `WAIT_DONE_ACK` | `LINK_CMD_SEND_CTRL(target_id, session_id, DONE, 0)` |
| reset | `LINK_CMD_SESSION_RESET(session_id)` |

## Anchor APP 状态机

```
IDLE
  |
  | DATA_CFG event
  v
ACTIVE
  |
  | DATA_CTRL(GET_INFO/PULL)
  | prepare payload slot and send LINK_CMD_SEND_FRAG
  |
  | DATA_CTRL(DONE/STOP)
  v
IDLE
```

Anchor APP 行为:

- 收到 `DATA_CFG`: 检查是否可建立新会话, 准备发送缓冲和 meta。
- 收到 `DATA_CTRL(GET_INFO)`: 写 meta payload 到 APP slot, 下发 `LINK_CMD_SEND_FRAG`。
- 收到 `DATA_CTRL(PULL)`: 写指定分片到 APP slot, 下发 `LINK_CMD_SEND_FRAG`。
- 收到 `DATA_CTRL(DONE)`: 下发 `LINK_CMD_SEND_ACK`, 释放 APP 会话。
- 会话超时或冲突: 下发 `LINK_CMD_SESSION_RESET` 或让 LINK/PHY 返回 ERROR。

## LINK 传输子状态

LINK 对每条 APP 命令执行一次非阻塞传输:

```
IDLE
  |
  | consume UwbLinkCmd
  v
WAIT_TX_DONE
  |
  | PHY_EVT_TX_DONE
  v
WAIT_RX
  |
  | RX response / RX timeout / ERROR
  v
IDLE or WAIT_RETRY_TX
```

状态含义:

| 状态 | 含义 |
|------|------|
| `IDLE` | 可接受下一条 APP 命令 |
| `WAIT_TX_DONE` | DATA 帧已提交 PHY, 等待发送完成 |
| `WAIT_RX` | Tag 侧等待 ACK/FRAG/WAIT/ERROR |
| `WAIT_RETRY_TX` | 本次交换失败, 准备重发当前 slot |

LINK 不推进 APP 的 CFG/META/DATA/DONE 业务状态。LINK 只把 ACK/FRAG/WAIT/ERROR/FAIL 上报给 APP。

## Anchor LINK 行为

Anchor LINK 是响应式:

1. `PHY_EVT_RX_FRAME(DATA_CFG)`: 解析 `session_id/src_id`, 上报 `UWB_LINK_APP_EVT_DATA_CFG`。
2. `PHY_EVT_RX_FRAME(DATA_CTRL)`: 解析 `session_id/ctrl_type/frag_id`, 上报 `UWB_LINK_APP_EVT_DATA_CTRL`。
3. `LINK_CMD_SEND_FRAG`: 将 APP slot 中 payload 封装为 `DATA_FRAG`, 登记备份, 下发 `PHY_CMD_LOAD_PENDING`。
4. `PHY_EVT_DATA_RETRY`: 从备份表取匹配 frag, 重新下发 `PHY_CMD_LOAD_PENDING`。
5. `LINK_CMD_SEND_ACK`: 构建 `DATA_CTRL_RESP` 发送。
6. `LINK_CMD_SESSION_RESET`: 清理 DATA slot 和 PHY pending。

## 事件路由

### Tag 收到响应

| 帧 | LINK 处理 |
|----|-----------|
| `DATA_CTRL_RESP(ACK)` | 释放响应 slot, 上报 `DATA_ACK` |
| `DATA_CTRL_RESP(WAIT)` | 释放响应 slot, 上报 `DATA_WAIT` |
| `DATA_CTRL_RESP(ERROR)` | 释放响应 slot, 上报 `DATA_ERROR`, 复位 DATA transport |
| `DATA_FRAG` | 解析 meta, 转交 APP, slot 由 APP 释放 |

### Anchor 收到请求

| 帧 | LINK 处理 |
|----|-----------|
| `DATA_CFG` | 上报 `DATA_CFG`, slot 由 LINK 解析后释放 |
| `DATA_CTRL(GET_INFO)` | 上报 `DATA_CTRL`, slot 由 LINK 解析后释放 |
| `DATA_CTRL(PULL)` | 上报 `DATA_CTRL`, slot 由 LINK 解析后释放 |
| `DATA_CTRL(DONE/STOP)` | 上报 `DATA_CTRL`, slot 由 LINK 解析后释放 |

## 与测距交织

LINK 调度的单位是一条 APP DATA 命令, 不是完整 APP 会话。

```
DISC, DISC, DATA(CFG), DISC, DATA(GET_INFO), DISC, DATA(PULL#1), DISC, ...
```

规则:

- DATA transport 忙时不提交新的 DATA。
- DISC pipeline 未满时优先补 DISC。
- 每完成至少 2 次 DISC 后, 如果 APP 命令队列有 DATA 命令, 插入 1 次 DATA 交换。
- DATA 交换完成后回到调度器, APP 决定是否下发下一条 DATA 命令。

这样可以避免一次完整数据会话期间测距停止。

## 复位

`data_sm_reset()` 是 LINK 的 DATA 资源复位, 不等于 APP 业务复位。

必须清理:

- LINK 数据挂起表。
- DATA 当前 TX/RX/retry slot。
- PHY pending frag。
- 残留 DATA 事件。

不能清理:

- DISC/TWR 的协议定义。
- APP 测距记录。
- GNSS/IMU/SD 业务数据流。
