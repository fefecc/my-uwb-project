# UWB 数据交互帧实施文档

## 实施边界

本文只描述后续代码实施顺序。当前提交只整理文档, 不修改 C 代码。

实施必须遵循:

- APP 决定 `target_id` 和 `session_id`。
- LINK 只执行帧封装、调度、重试、slot 管理和事件上报。
- PHY 只作为 TX/RX、快速 ACK、pending frag delayed TX 工具层。
- DISC/TWR 帧格式不改。
- 现有测距结果计算不改。

## 当前代码基线

已存在:

- `UWB_FUNC_APP_DATA_CFG/FRAG/CTRL/CTRL_RESP`
- `LINK_CMD_SEND_CFG_REQ/SEND_CTRL/SEND_FRAG/SEND_ACK/SESSION_RESET`
- `UWB_LINK_APP_EVT_DATA_*`
- `UwbLinkCmd_Send()` / `UwbLinkCmd_Recv()`
- `PHY_CMD_LOAD_PENDING`
- `PHY_EVT_DATA_RETRY`
- 16-slot 池和 `UWB_SLOT_APP_OWN`

尚未完成:

- `UwbLinkCmd` 缺少 `target_id`。
- `UwbLink_SendCmd()` 直接返回 `false`。
- LINK 未消费 APP->LINK 命令。
- LINK 未构建/解析 DATA 帧。
- LINK 未处理 `PHY_EVT_DATA_RETRY`。
- APP 未实现 Tag/Anchor 数据会话。

## 步骤 1: 补齐 APP->LINK 命令接口

文件:

- `APP/UWB/uwb_buffers.h`

修改 `UwbLinkCmd`:

```c
typedef struct {
    UwbLinkCmdType type;
    int8_t   slot_index;
    uint16_t target_id;
    uint16_t session_id;
    uint8_t  ctrl_type;
    uint8_t  frag_id;
    uint8_t  resp_type;
} UwbLinkCmd;
```

字段规则:

- `target_id`: APP 选择的对端短地址, LINK 写入 MAC `dst16`。
- `session_id`: APP 生成的会话号。
- `slot_index`: APP 提供 payload slot 时有效, 无 slot 时为 -1。
- `ctrl_type`: `GET_INFO/PULL/DONE/STOP`。
- `frag_id`: `PULL` 或 `DATA_FRAG` 时有效。
- `resp_type`: `ACK/WAIT/STOP/ERROR`。

## 步骤 2: 接入 LINK 命令队列

文件:

- `APP/UWB/uwb_link.c`

实现:

- `UwbLink_SendCmd(const UwbLinkCmd *cmd)` 调用 `UwbLinkCmd_Send(cmd, 0)`。
- 新增 `link_dispatch_app_cmd()`。
- 新增 `drain_app_cmds()` 或并入 `link_event_monitor()`。

规则:

- Tag 只接受 `LINK_CMD_SEND_CFG_REQ` 和 `LINK_CMD_SEND_CTRL`。
- Anchor 只接受 `LINK_CMD_SEND_FRAG`、`LINK_CMD_SEND_ACK`、`LINK_CMD_SESSION_RESET`。
- 命令队列 depth=1, APP 失败后自行暂存并下周期重试。
- LINK 不修改 `target_id`, 不自行选择目标。

## 步骤 3: 增加 DATA 帧构建

文件:

- `APP/UWB/uwb_link.c`

新增构建函数:

- `build_data_cfg_req(target_id, session_id)`
- `build_data_ctrl(target_id, session_id, ctrl_type, frag_id)`
- `build_data_frag(target_id, session_id, frag_id, total_frags, flags, slot_index)`
- `build_data_ctrl_resp(target_id, resp_type, extra)`

帧头约定:

| 帧 | ext header |
|----|------------|
| `DATA_CFG` | `session_id` little-endian 2B |
| `DATA_CTRL` | `session_id` 2B + `ctrl_type` 1B + `frag_id` 1B |
| `DATA_FRAG` | `session_id` 2B + `frag_id` 1B + `total_frags` 1B + `flags` 1B |
| `DATA_CTRL_RESP` | `resp_type` 1B + `extra` 1B |

`DATA_FRAG` payload 由 APP 写入 slot。LINK 可以先把 payload 暂存到本地小缓冲再 encode 回同一 slot, 或使用现有协议结构体重新写 slot。实现必须保证失败时释放 APP slot。

## 步骤 4: 增加 DATA 帧解析与事件上报

文件:

- `APP/UWB/uwb_link.c`

扩展 `link_dispatch_phy_evt()`:

- `PHY_EVT_RX_SLOT_DONE`:
  - `DISC_RESP`: 保持当前测距逻辑。
  - `DATA_CTRL_RESP`: 解析 ACK/WAIT/ERROR/STOP, 上报 APP, 释放 slot。
  - `DATA_FRAG`: 解析 header, 上报 `UWB_LINK_APP_EVT_DATA_FRAG`, slot 转交 APP。
- `PHY_EVT_RX_FRAME`:
  - `DATA_CFG`: 解析 `src_id/session_id`, 上报 `UWB_LINK_APP_EVT_DATA_CFG`, 释放 slot。
  - `DATA_CTRL`: 解析 `src_id/session_id/ctrl_type/frag_id`, 上报 `UWB_LINK_APP_EVT_DATA_CTRL`, 释放 slot。
- `PHY_EVT_DATA_RETRY`:
  - 从 LINK 数据挂起表取备份 frag, 重新下发 `PHY_CMD_LOAD_PENDING`。

未知帧统一释放 slot。

## 步骤 5: 增加 DATA slot 挂起表和复位

文件:

- `APP/UWB/uwb_link.c`

新增:

```c
typedef struct {
    int8_t   slot_index;
    uint16_t target_id;
    uint16_t session_id;
    uint8_t  frag_id;
    uint8_t  flags;
} link_data_slot_entry_t;
```

建议 `LINK_DATA_SLOT_MAX=4`。

实现函数:

- `link_data_slot_register()`
- `link_data_slot_find(session_id, frag_id)`
- `link_data_slot_unregister(slot_index)`
- `link_data_slot_free_all()`
- `data_sm_reset()`

`data_sm_reset()` 必须:

- 回收 LINK 数据挂起表。
- 回收当前 DATA TX/retry slot。
- 下发 `PHY_CMD_LOAD_PENDING` with `slot_index=-1` 清 PHY pending。
- 必要时下发 `PHY_CMD_RESET`。
- 丢弃残留 DATA 事件。
- 不清理 DISC/TWR 业务状态。

## 步骤 6: 实现 LINK 调度

文件:

- `APP/UWB/uwb_link.c`

Tag 调度:

1. 每轮先 drain PHY events 和 APP commands。
2. DATA transport 忙时只做 timeout/retry。
3. DATA 空闲时优先补 DISC pipeline。
4. `g_disc_count >= 2` 且 APP 命令队列有 DATA 命令时, 执行 1 次 DATA 交换。
5. DATA 交换完成后回到调度器, APP 决定下一条命令。

Anchor 调度:

- 始终 drain PHY events。
- 始终 drain APP commands。
- 收到 APP `SEND_FRAG` 时只预载 pending, 不主动选择目标。

测距要求:

- `build_disc_req()` 不改。
- `DISC_RESP` 解析和 `UWB_LINK_APP_EVT_TWR_EXCHANGE` 上报不改。
- 任何 DATA 复位不能重置 APP 测距记录。

## 步骤 7: 实现 APP 会话

文件:

- `APP/UWB/uwb_app.c`
- `APP/UWB/uwb_app.h`

Tag APP:

- 维护 MAC/Anchor 候选表。
- 选择 `target_id`。
- 生成 `session_id`。
- 依次下发 CFG、GET_INFO、PULL、DONE。
- 接收 DATA_FRAG 后校验 CRC 并拼装。
- 失败时下发 `LINK_CMD_SESSION_RESET`。

Anchor APP:

- 收到 DATA_CFG 后建立会话。
- 准备 230 字节假数据和 meta。
- 收到 GET_INFO/PULL 后写 payload slot 并下发 `LINK_CMD_SEND_FRAG`。
- 收到 DONE 后下发 `LINK_CMD_SEND_ACK` 并清理会话。

## 步骤 8: 最小测试

按 `最小测试环路.md` 验收:

- Anchor 上电打印 `TX buf len=230` 和 5 句假数据。
- Tag 拉取 meta: `data_len=230`, `total_frags=4`。
- Tag 拉取 4 个 data frag。
- Tag 打印 `SESSION_COMPLETE` 和 5 句内容。
- 数据会话期间仍有 TWR 日志。
- DATA reset 后 DISC/TWR 继续。
