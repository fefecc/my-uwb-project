# 基站初始化 — 近距离信息表构建与 Tag 拉取方案

## 概述

本方案定义基站（Anchor）自组织初始化流程：按键触发后，基站互相发现、测距 30 秒，构建近距离信息表。Tag 开机后从每个基站拉取该表写入 SD 卡。

这是最终版本，所有后续实现以此为基准。

## 硬件资源

### LED 状态指示

板载 4 颗 LED，初始化阶段用 3 颗指示状态，LED_3 留给正常运行：

| LED | 引脚 | 初始化阶段含义 |
|-----|------|---------------|
| LED_0 | PE4 | 空闲/等待按键 |
| LED_1 | PE5 | 正在发现/测距 |
| LED_2 | PE6 | 初始化完成 |
| LED_3 | PC13 | （保留给正常运行） |

状态指示：

| 阶段 | LED 表现 |
|------|---------|
| 等待按键 | LED_0 慢闪 (1Hz) |
| 发现阶段 | LED_1 快闪 (4Hz) |
| 测距阶段 | LED_1 常亮 |
| 传递距离表 | LED_1 + LED_2 交替闪烁 |
| 初始化完成 | LED_2 常亮 |
| 错误 | LED_0 + LED_1 + LED_2 全亮 |

### 按键

- USER_KEY (PE2)：短按触发初始化流程

## 整体流程

```
┌─────────────────────────────────────────────────────┐
│                   Anchor 初始化流程                    │
├─────────────────────────────────────────────────────┤
│                                                     │
│  [按键] → Phase 1: 发现                               │
│           Anchor 广播 DISC_REQ，发现附近所有 Anchor     │
│                                                     │
│         → Phase 2: 测距 (~30s)                       │
│           与每个发现的 Anchor 持续 TWR 测距             │
│           累积样本，结束取平均                          │
│                                                     │
│         → Phase 3: 传递距离表                         │
│           按 ID 顺序，把本地距离表传给下一个 Anchor      │
│           下一个 Anchor 追加自己的数据后继续传递          │
│           直到回到发起者 ID，结束                        │
│                                                     │
│         → Phase 4: 就绪                              │
│           进入正常工作模式，等待 Tag 连接               │
│                                                     │
├─────────────────────────────────────────────────────┤
│                   Tag 侧流程                          │
├─────────────────────────────────────────────────────┤
│                                                     │
│  Tag 开机 → 正常 Discovery + TWR 测距                 │
│          → 向每个 Anchor 拉取近距离信息表 (一次)        │
│          → 写入 SD 卡                                 │
│                                                     │
└─────────────────────────────────────────────────────┘
```

## Phase 1: 发现阶段

### 触发

Anchor 上电后处于空闲状态。用户短按按键 → 启动初始化流程。

### 发现过程

Anchor 以 Tag 角色发送 DISC_REQ 广播帧，收到其他 Anchor 的 DISC_RESP。

持续发现 5 秒，记录所有响应的 Anchor ID。

发现结果存入本地表：

```c
#define INIT_MAX_ANCHORS  8

typedef struct {
    bool     valid;
    uint16_t anchor_id;
    bool     discovered;
} init_anchor_entry_t;

typedef struct {
    uint16_t self_id;
    uint16_t pan_id;
    uint8_t  anchor_count;
    init_anchor_entry_t anchors[INIT_MAX_ANCHORS];
} init_discovery_table_t;
```

## Phase 2: 测距阶段

### 测距策略

对发现的每个 Anchor 持续 TWR 测距，持续 30 秒。

测距使用现有 DS-TWR 流程，复用 Discovery + Ranging 链路。

### 样本累积

每个 Anchor 维护一个样本缓冲：

```c
#define INIT_RANGING_DURATION_MS  30000U
#define INIT_RANGING_SAMPLES_MAX  512U

typedef struct {
    uint16_t anchor_id;
    uint16_t sample_count;
    float    distance_sum;
    uint32_t pacc_sum;
    /* 不存原始样本，只累加，省内存 */
} init_ranging_accum_t;
```

每次 TWR 完成回调中：

```c
accum->distance_sum += result->distance_m;
accum->pacc_sum     += result->quality.rx_pacc;
accum->sample_count++;
```

30 秒结束后计算平均值：

```c
avg_distance = accum->distance_sum / accum->sample_count;
avg_pacc     = accum->pacc_sum / accum->sample_count;
```

## 近距离信息表（Anchor Proximity Table）

### 数据结构

整个表控制在 512 字节以内，通过 DATA 帧传递。

```c
#define PROX_TABLE_MAX_ENTRIES  16
#define PROX_TABLE_VERSION      1

/* 单条距离记录 */
typedef struct {
    uint16_t anchor_a;          /* 较小 ID 的 Anchor */
    uint16_t anchor_b;          /* 较大 ID 的 Anchor */
    uint16_t avg_pacc;          /* 平均信号质量 */
    uint16_t sample_count;      /* 测距样本数 */
    uint16_t reserved;          /* 对齐 */
    float    distance_m;        /* 平均距离 (米) */
} prox_entry_t;                 /* 14 字节 */

/* 近距离信息表 */
typedef struct {
    uint8_t  version;           /* 版本号 = 1 */
    uint8_t  entry_count;       /* 有效条目数 */
    uint16_t source_anchor;     /* 本表由谁生成 (Anchor ID) */
    uint32_t timestamp_ms;      /* 生成时的本地时间 */
    uint32_t reserved;
    prox_entry_t entries[PROX_TABLE_MAX_ENTRIES];
} prox_table_t;                 /* 8 + 14*16 = 232 字节 */
```

232 字节，满足 512 字节限制。一个 DATA 会话可传完（230 字节 payload，刚好 4 个分片）。

### 传递链协议

Phase 3 按 Anchor ID 顺序接力传递距离表。

**规则：** 按 ID 排序，从当前 Anchor 传给下一个更大 ID 的 Anchor。如果当前是最大 ID，传给最小 ID，形成环形。

**示例：** 发现了 0x0030, 0x0031, 0x0032, 0x0033

```
0x0031 (发起者，自己的表先填好)
  → 传给 0x0032 (0x0032 追加自己的距离数据)
    → 传给 0x0033 (追加)
      → 传给 0x0030 (追加，0x0030 是最小 ID)
        → 传回 0x0031 (回到发起者，结束)
```

**"下一个"的确定算法：**

```c
// 按 ID 排序后的 anchor 列表
// sorted_ids[] = {0x0030, 0x0031, 0x0032, 0x0033}
// 找到 self_id 的位置，下一个就是 (pos + 1) % count
// 如果 self_id 是最后一个，下一个是第一个（环形）
```

### 传递帧格式

复用现有 DATA 帧协议：

- `DATA_CFG_REQ`: src 通知 dst "我要传距离表给你"
- `DATA_FRAG`: 携带 `prox_table_t` 序列化数据
- `DATA_CTRL_RESP ACK`: dst 确认收到

Anchor 收到表后：
1. 解析 `prox_table_t`
2. 遍历自己的测距结果，把 `self ↔ other_anchor` 的距离追加为新的 `prox_entry_t`
3. `entry_count++`
4. 按"下一个"算法传给下一个 Anchor

### 冲突与超时

- 传递超时：单个 Anchor 收到表后 5 秒内必须传给下一个
- 传递失败（下一个 Anchor 不在线）：跳过该 Anchor，传给再下一个
- 最多重试 2 次，全部失败则本 Anchor 保留不完整的表，直接进入就绪状态

## Phase 4: 就绪

传递完成后，Anchor 进入正常工作模式：

- LED_2 常亮
- 正常响应 Tag 的 Discovery 和 TWR
- 准备好响应 Tag 的距离表拉取请求

## Tag 侧拉取流程

### 触发

Tag 正常启动后（Discovery + TWR 正常运行），在首次发现 Anchor 时，从该 Anchor 拉取近距离信息表。

**每个 Anchor 只拉取一次。**

### 拉取过程

复用现有 DATA 帧协议：

1. Tag 向 Anchor 发送 `DATA_CTRL_PULL`（新增 ctrl_type = 拉取距离表）
2. Anchor 回复 ACK，然后发送 `prox_table_t` 数据
3. Tag 收到后写入 SD 卡

### SD 卡存储

每个 Anchor 的距离表写为一个独立文件：

```
uwb-anchor-prox-0031.bin    // Anchor 0x0031 的近距离信息表
uwb-anchor-prox-0032.bin    // Anchor 0x0032 的近距离信息表
...
```

文件内容就是 `prox_table_t` 结构体的原始二进制，232 字节。

### Tag 侧记录

```c
#define TAG_MAX_ANCHORS  8

typedef struct {
    uint16_t anchor_id;
    bool     pulled;          /* 已拉取 */
} tag_pull_record_t;

static tag_pull_record_t g_pull_records[TAG_MAX_ANCHORS];
```

Tag 每次收到 Anchor 的 Discovery 响应时检查：如果该 Anchor 尚未拉取，启动拉取流程。

## 双向距离合并

每个 Anchor 对之间会有两组距离数据：
- Anchor A 测到 Anchor B 的距离
- Anchor B 测到 Anchor A 的距离

传递过程中两组数据都保留在表中（作为两条 `prox_entry_t`，方向不同）。

后处理时取平均即可，不在嵌入式端合并，留给上位机分析脚本处理。

```
entry[0]: anchor_a=0x0030, anchor_b=0x0031, distance=1.23m  (0x0031 测的)
entry[1]: anchor_a=0x0030, anchor_b=0x0031, distance=1.25m  (0x0030 测的)
```

最终距离 = (1.23 + 1.25) / 2 = 1.24m

## 状态机

### Anchor 初始化状态机

```
IDLE ──[按键]──→ DISCOVERING ──[5s超时]──→ RANGING ──[30s超时]──→ PASSING
                     │                                        │
                     └──[无发现]──→ ERROR                      └──[传递完成]──→ READY
```

```c
typedef enum {
    INIT_STATE_IDLE = 0,
    INIT_STATE_DISCOVERING,
    INIT_STATE_RANGING,
    INIT_STATE_PASSING,
    INIT_STATE_READY,
    INIT_STATE_ERROR,
} init_state_t;
```

### LED 映射

```c
static void update_init_led(init_state_t state)
{
    BspLed_AllOff();
    switch (state) {
    case INIT_STATE_IDLE:
        /* LED_0 慢闪由 LED Task 处理 */
        break;
    case INIT_STATE_DISCOVERING:
        BspLed_Set(BSP_LED_1, true);   /* 快闪由周期翻转实现 */
        break;
    case INIT_STATE_RANGING:
        BspLed_Set(BSP_LED_1, true);   /* 常亮 */
        break;
    case INIT_STATE_PASSING:
        BspLed_Toggle(BSP_LED_1);
        BspLed_Toggle(BSP_LED_2);
        break;
    case INIT_STATE_READY:
        BspLed_Set(BSP_LED_2, true);   /* 常亮 */
        break;
    case INIT_STATE_ERROR:
        BspLed_Set(BSP_LED_0, true);
        BspLed_Set(BSP_LED_1, true);
        BspLed_Set(BSP_LED_2, true);
        break;
    }
}
```

## 数据流总结

```
Anchor 初始化:
  按键 → DISC广播 → 发现 N 个 Anchor
      → 30s TWR测距 → 累积样本 → 取平均
      → 构建 prox_table_t (232B)
      → 按 ID 顺序接力传递 → 每个 Anchor 追加自己的数据
      → 回到发起者 → 初始化完成

Tag 拉取:
  Tag 开机 → 正常 Discovery
          → 发现 Anchor → 检查是否已拉取
          → 未拉取 → 发 DATA_CTRL_PULL_PROX
          → 收到 prox_table_t → 写 SD (uwb-anchor-prox-XXXX.bin)
          → 标记已拉取，不再重复
```
